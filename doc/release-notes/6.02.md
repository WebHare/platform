# WebHare 6.02 release notes

## Breaking changes

### OpenID Connect issuer is now derived from the identity provider site
WebHare no longer stores a configurable OpenID Connect `issuer` per WRD schema. The issuer is now always the webroot
of the site that has the `platform:identityprovider` webfeature for that schema, without the trailing slash (eg.
`https://login.example.net`). This is what RFC 8414 and OpenID Connect Discovery require: the issuer must match the
location the metadata is served from.

If your schema's previous issuer was different from that webroot (by default it was the backend URL), the `iss` claim
in ID tokens changes after the upgrade. Relying parties that have the old issuer configured will reject new
ID tokens until they are updated with the new issuer. Run `wh auth describe` to see the new value.

Whether a schema acts as an OpenID Connect provider is now controlled by `openIdServer` in the schema's
`loginSettings`. Schemas which had an issuer configured are migrated to `openIdServer: true` automatically.

You can enable or disable it with the 'OpenID Connect provider' checkbox on the OAuth tab of the WRD schema properties.

- `wh auth idp-setup` no longer accepts `--issuer`. It now only enables the schema as an OpenID Connect provider
- `initializeIssuer()` in `@webhare/auth` is deprecated and ignores its `issuer` parameter. Use `enableOpenIDServer()`
  instead
- `getOpenIDIssuer()` in `@webhare/auth` returns the issuer for a schema
- `getOpenIDMetadataURL()` now returns `null` if the schema isn't an OpenID Connect provider
- The keys returned by the JWKS endpoint no longer have an (unofficial) `issuer` property

## OAuth2 and dynamic client registration
WRD schemas can now act as a plain OAuth2 authorization server without being an OpenID Connect provider. This is
enough for dynamic client registration (RFC 7591) and for MCP clients.

- `/.well-known/oauth-authorization-server` (RFC 8414) is served for every identity provider site
- `/.well-known/openid-configuration` is only served if `loginSettings.openIdServer` is enabled. Otherwise it
  returns 404, and the `openid`, `profile` and `email` scopes and the userinfo endpoint are unavailable.
