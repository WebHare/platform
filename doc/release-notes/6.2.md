# WebHare 6.2 release notes

## Breaking changes

### OpenID Connect issuer is now derived from the identity provider site
WebHare no longer stores a configurable OpenID Connect `issuer` per WRD schema. The issuer is now always the webroot
of the site that has the `platform:identityprovider` webfeature for that schema, without the trailing slash (eg.
`https://login.example.net`). This is what RFC 8414 and OpenID Connect Discovery require: the issuer must match the
location the metadata is served from.

If your schema's previous issuer was different from that webroot (by default it was the backend URL), the `iss` claim
in ID tokens changes after the upgrade. Relying parties that have the old issuer configured will reject new
ID tokens until they are updated with the new issuer. Run `wh auth describe` to see the new value.

Whether a schema acts as an OpenID Connect provider is now controlled by `openIdServer` in the schema's
`loginSettings`. Schemas which had an issuer configured are migrated to `openIdServer: true` automatically.

You can enable or disable it with the 'OpenID Connect provider' checkbox on the OAuth tab of the WRD schema properties.

- `wh auth idp-setup` no longer accepts `--issuer`. It now only enables the schema as an OpenID Connect provider
- `initializeIssuer()` in `@webhare/auth` is deprecated and ignores its `issuer` parameter. Use `enableOpenIDServer()`
  instead
- `getOpenIDIssuer()` in `@webhare/auth` returns the issuer for a schema
- `getOpenIDMetadataURL()` now returns `null` if the schema isn't an OpenID Connect provider
- The keys returned by the JWKS endpoint no longer have an (unofficial) `issuer` property

### WRD API uses modern field names
The `/wrd/` endpoints of the WebHare API (`.wh/api/v1/`) now use the same field names as the modern `wrd()` API in
`@webhare/wrd`, instead of the legacy names. This applies to the fields you select in queries, the fields returned
in query results and the fields you pass when creating or updating entities:

| Legacy name           | New name            |
|-----------------------|---------------------|
| `wrdCreationDate`     | `wrdCreated`        |
| `wrdLimitDate`        | `wrdClosed`         |
| `wrdModificationDate` | `wrdModified`       |
| `wrdOrdering`         | `wrdOrder`          |
| `wrdInfix`            | `wrdLastNamePrefix` |

Requests that still use a legacy name now fail with an error. Update any integration that selects, reads or sends
these fields to use the new names.

The `wh wrd` commands have made the same switch: `export` and `get-setting` output the new names, and
`create-entity`, `update-entity` and `update-setting` expect them in their input.

### HareScript regular expressions now closely follow ECMAScript
`RegEx` from `wh::regex.whlib` now closely follows the syntax and behaviour of JavaScript's `RegExp`. Most patterns,
flags and replacement strings work the same in HareScript and in JavaScript/TypeScript (see the known differences
below). The native engine uses PCRE2 instead of the C++ standard library's `std::regex`. The WASM engine uses
JavaScript's `RegExp`, always in `u` mode (patterns without the `u` flag are translated).

Besides the `g`, `i` and `m` flags, the `u` (unicode) flag is now supported. Other flags, lookbehind assertions, named
capture groups and modifiers (eg `(?i:...)`) are not supported.

`JSRegEx` is deprecated. It is now identical to `RegEx`, so replace `NEW JSRegEx(...)` with `NEW RegEx(...)`.

Patterns that may behave differently:
- The `m` flag now works. Without it, `^` and `$` only match at the start and end of the input. Before, `m` had no
  effect.
- Patterns work on Unicode characters instead of bytes. For example, `.` matches `é` as one character. Positions
  (`start`, `len` and `lastindex`) are still UTF-8 byte offsets. Character classes containing non-ASCII characters used
  to match the individual bytes of those characters, so eg `[“”]` also matched parts of `—` and `‘`. They now only match
  the listed characters.
- POSIX character classes like `[[:alpha:]]` are no longer supported. As in JavaScript, `[[:alpha:]]` is now a class of
  the characters `[:alph` followed by a literal `]`. Replace them with explicit classes, eg `[a-zA-Z]`.
- With the `i` flag, non-ASCII letters now also match case-insensitively (eg `é` matches `É`).
- `\s` now also matches non-ASCII whitespace, like non-breaking spaces. `\d`, `\w` and `\b` still only match ASCII.
- A backreference to a group that didn't participate in the match now matches an empty string.
- `lastindex` follows JavaScript's rules. `Exec` and `Test` only use and update it for regular expressions with the `g`
  flag. A search from `lastindex` also looks at the text before it: `^` doesn't match there, but `\b` can. A
  `lastindex` inside a character continues at the next character.
- `Replace` and `ReplaceCallback` return the whole input, including any text before `lastindex`.
- Some patterns that used to throw are now accepted, as they are in JavaScript without the `u` flag:
  - a `{`, `}` or `]` that isn't part of a quantifier or class matches itself
  - unknown or incomplete escapes like `\A`, `\Q`, `\x4` or `\c1` mean the literal text
  - `\8` and `\9` mean the digits, and `\1` to `\7` without a matching group are octal escapes
  - a `-` next to a class escape (eg `[\w-a]`) is a literal `-`
  - a quantifier can follow a lookahead assertion (eg `(?=a)*`)

  Syntax that JavaScript rejects, like possessive quantifiers, atomic groups and `(?i)`-style inline flags, still
  throws.
- Error messages for invalid patterns have changed. They now start with `Invalid regular expression: /pattern/flags:`.

Known differences with JavaScript in both engines:
- Characters outside the Basic Multilingual Plane (eg emoji) are always a single character, also without the `u` flag.
  Without `u`, JavaScript sees them as two UTF-16 code units, so eg `.` only matches half of an emoji there.
- With the `i` flag, letters are always compared as JavaScript does with the `u` flag, so eg `ſ` (long s) matches `s`
  and `K` (Kelvin sign) matches `k`.

Known differences in the native engine:
- Without the `u` flag, a class range of characters outside the Basic Multilingual Plane (eg `[😀-🙏]`) isn't rejected.
  JavaScript (and so the WASM engine) rejects it, as it sees two UTF-16 code units. Use the `u` flag for such ranges.
- With the `u` flag, a quantifier on a lookahead assertion (eg `(?=a)*`) isn't rejected. Don't use it, as JavaScript
  doesn't allow it (so it doesn't work in WASM mode).
- U+2028 and U+2029 aren't line terminators.
- In `m` mode, `^` and `$` don't match between the CR and LF of a CRLF.
- With the `i` flag, `\w`, `\W`, `\b` and `\B` don't consider `ſ` (long s) and `K` (Kelvin sign) to be word characters.
  JavaScript does in `u` mode, and so does the WASM engine.

Building WebHare from source now requires PCRE2 10.43 or newer: `pcre2` from Homebrew, or `pcre2-devel` on Linux.

### `toFSPath` rejects `.` and `..` path segments
`toFSPath` in `@webhare/services` now throws for resource paths that contain `.` or `..` segments, eg.
`mod::mymodule/data/../x` or `@mod-mymodule/./lib/`. This also applies with `allowUnmatched` or `keepUnmatched`, and
for modules that don't exist. Paths that aren't resource paths (eg. disk paths passed with `keepUnmatched`) are still
returned as-is.

If you build a resource path from external input, pass a `root` option (a resource path, eg. `mod::mymodule/data/`).
With a `root`, `.` and `..` segments are allowed as long as the result stays inside that root and inside the module or
storage folder, and paths without dot segments must be inside the root too. Alternatively, normalize the path first
with `resolveResource`.

### `consilioFields` names set from TypeScript are now indexed as snake_case
Field names in `pageMetadata.consilioFields` set by TypeScript pages are now converted from camelCase to snake_case
before they are indexed, including the names inside nested records. Previously they were lowercased, so `pageType`
was indexed as `pagetype`. It's now indexed as `page_type`.

If your TypeScript pages set camelCase names in `consilioFields`, update the catalog field definitions and any search
code that refers to these fields, and reindex the affected catalogs. Fields set from HareScript are not affected.

### Unused HareScript graphics APIs removed
The `wh::graphics/` libraries only work on the native HareScript engine and are being phased out. The following APIs
were removed, together with the native code behind them. HareScript code that still uses them no longer compiles
(functions) or fails when the call is reached (canvas and path members):

- `wh::graphics/core.whlib`:
  - Canvases: `GfxCreateCanvas`, `GfxCreateCanvasFromRAWBlob`, `GfxCreateRAWBlobFromCanvas`, `GfxCreateDifferenceCanvas`,
    `GfxCompareCanvases`, `GfxCountCanvasColors` and `GfxDimensionsFromImageBlob` (use `ScanBlob`).
  - Modes and pixels: `GfxSetAlphaMode`, `GfxGetAlphaMode`, `GfxSetPixelMode`, `GfxGetPixelMode`, `GfxGetPixel` and
    `GfxDrawPixel`.
  - Paths: `GfxRenderPath`, `GfxDrawPath`, `GfxDrawFillPath`, `GfxFillPath`, `GfxTextureFillPath`,
    `Gfx3dTextureFillPath`, `GfxPathMoveTo`, `GfxPathLineTo`, `GfxPathClose`, `GfxPathClosePath`, `GfxPathArcTo`,
    `GfxPathArcToR` and `GfxPathBezierTo`.
  - Shapes: `GfxDrawLine`, `GfxDrawRectangleBorder`, `GfxDrawCircle` and `GfxDrawCircleBorder`.
- `wh::graphics/filters.whlib`: `GfxApplyColorMapping`, `GfxGrayscaleCanvas`, `GfxUpdateCanvasAlpha`, `GfxInvertCanvas`
  and `GfxResizeCropImageBlob` (use `ResizeImage` from `mod::platform/lib/graphics.whlib` with method `fill`).
- `wh::graphics/canvas.whlib`: `CreateCanvasFromRawBlob`, the canvas members `DrawPixel` (use `SetPixel`), `GetPixel`,
  `MultiplyAlpha`, `AddAlpha`, `Blur`, `Grayscale`, `SetImageWidth`, `SetImageHeight` (use `SetImageSize`) and
  `Mirror`, and the path members `Clone`, `BezierTo`, `ArcTo`, `ArcToR` and `SmoothBezierCurve`. Paths now only
  consist of `MoveTo`, `LineTo` and `ClosePath` segments.

Canvases can no longer be sent over IPC links or to jobs. Sending one now fails like any other object that cannot be
marshalled. Send the image as a blob instead (eg. `canvas->ExportAsPNG`).

Prefer `mod::platform/lib/graphics.whlib` (`ResizeImage`, `GenerateQRCode`) or `@webhare/graphics` in TypeScript for
new code, as these work on both engines.

### Bitmapped text rendering removed from DrawLib
As announced in the WebHare 6.1 release notes, the DrawLib/`wh::graphics` APIs for rendering text into bitmaps have
been removed. Use SVGs or Puppeteer's screenshot API to generate images of text.

### HareScript SAX and MHTML APIs removed
The callback (SAX) based XML parser and the APIs built on it have been removed: `ParseXMLWithCallbacks`,
`ParseHTMLAsXMLWithCallbacks`, `ImportFromMHTML` and `RewriteHTMLDocumentTo`. Parse documents with the DOM based APIs
(eg. `MakeXMLDocument`) instead.

### Tollium menubars removed
Tollium screens no longer show a menubar. The menu is always offered through a toolbar button, and a screen with a
`menubar=` but no `<toolbar>` gets a toolbar automatically. The `forcemenubar` attribute is deprecated and has no
effect, the Publisher's menubar preference is gone, and support for `ul.wh-menubar` has been removed.

### Asynchronous Tollium event handlers are rejected
Exceptions thrown by `ASYNC` event handlers were lost, so screen validation now reports an error when a Tollium event
handler points to a function that returns an `OBJECT` (eg. an `ASYNC` function or a generator) where no `OBJECT` return
value is expected. Make the handler synchronous and use `WaitForPromise` for the asynchronous parts.

### Changing WRD metadata requires `writeMetadata`
Schema objects returned by `wrd()` in `@webhare/wrd` can be shared between callers, so they can no longer change the
schema's metadata. To create, update or delete types and attributes (eg. `createType`, `createAttribute`,
`updateAttribute`, `updateMetadata`), open the schema with `wrd(tag, { writeMetadata: true })`. This returns a
`WRDWritableSchema`, which is not shared with other callers.

### `unique` is no longer accepted on WRD date and time attributes
The `isunique` option (`unique="true"` in a schema definition) was accepted on `DATE`, `DATETIME` and `TIME`
attributes but never enforced: HareScript failed on save and the TypeScript API ignored it. Both APIs now reject it, so
a schema definition that sets it fails to apply. Remove the option from these attributes.

### API keys now expire after 7 days by default
First-party API keys created without an expiry date (by `createFirstPartyToken(..., "api", ...)`, `wh auth` or the WRD
OpenAPI endpoint) used to get the login expiry: 1 day, rounded to 4 AM. They now get the schema's
`loginSettings.apiTokenDuration`, which is 7 days unless configured otherwise.

### Siteprofile validation is stricter
- The YAML siteprofile `forms` keys `defaultStoreeDays` and `maxStoreeDays` were misspelled and never had any effect.
  They are now `defaultStoreDays` and `maxStoreDays`, and the misspelled keys fail validation.
- The `maxstoredays` attribute of `<formintegration>` in XML siteprofiles was ignored and now takes effect.
- Unknown keys in the object form of `baseProps` are now reported instead of silently ignored. The array form of
  `baseProps` is deprecated: switch to the object form.

### TypeScript RTD rendering follows the RTD type's block styles
`renderRTD` now renders each block with the container tag and class of the matching block style in the RTD type, just
like the HareScript renderer. Eg. a `p.mycustomstyle` whose style has `containertag="div"` renders as
`<div class="mycustomstyle">`, and blocks with an unknown class fall back to the default style. Text styles, links and
images that a block style doesn't allow are left out (images are replaced by their alt text). This changes the output
of TypeScript webdesigns that relied on the stored tags and classes being rendered as-is.

`renderRTD` accepts an `rtdType` option to render with a different RTD type than the page's. It also applies to RTDs
rendered by TypeScript widgets inside that RTD. `buildRTD` now accepts `div` blocks, and `h6` blocks get the default
class `heading6`.

### Pasted images in the RTE are downloaded by the browser
The rich text editor used to ask the server to download images in pasted content. The browser now downloads them and
uploads them like any other image. Images from servers that don't send CORS headers can no longer be imported and are
dropped. Only PNG, JPEG, GIF, WebP and AVIF images of at most 20 MB are accepted.

### Links to WebHare internal URLs are rejected in link fields
External links to `/.wh/`, `/.uc/`, `/.publisher/` and `/.system/` paths (eg. image cache links, previews and
downloads) now fail validation in `intextlink` fields, such as the RTE's hyperlink dialog. Where possible the error
names the file the link points to, so editors can use an internal link instead. Existing values remain accepted as
long as they aren't changed.

### TypeScript 6 and stricter module typechecking
- WebHare now uses TypeScript 6 and Node.js 26 type definitions, and targets ES2025. Module code may need fixes to
  typecheck again.
- OpenAPI types are now generated with `@hey-api/openapi-ts` instead of `openapi-typescript`, which may change the
  generated types.
- A module's TypeScript configuration now only includes the RPC service types and `@mod-...` path mappings of the
  module itself, the built-in modules and the modules it depends on (including indirect dependencies). If your module
  uses another module's code or RPC services, declare it as a `<dependency module="..."/>` in the `<packaging>`
  section of your `moduledefinition.xml`.
- `@webhare/eslint-config` now warns about non-string values in `+` and template string expressions
  (`restrict-plus-operands` and `restrict-template-expressions`).

### Smaller incompatibilities
- `runCli` in `@webhare/cli` now passes arguments to your handlers under camelcased names (eg. an argument
  `<module-name>` becomes `args.moduleName`). Argument names may no longer contain uppercase letters.
- HareScript file and process functions now throw when a path or process argument contains a NUL byte, as the
  operating system would only see the part before it.
- `createOAuth2Client` and `fetchUserInfo` in `@webhare/auth` now take a `WRDEntityMatch` (an entity ID or an object
  with field values) to identify the server or provider.
- `registerRelyingParty` in `@webhare/auth` is now `registerOAuthApplication`.
- When both preparing a commit and the rollback after it fail, `commit()` now throws an `AggregateError` containing
  both errors.
- `ApplyWebHareConfiguration` and `executeApply` throw when passed an empty list of subsystems, which never did
  anything.
- The legacy test steps `waitforgestures` and `test.wait("pointer")`/`test.wait("animationframe")` have been removed.
  Await the last `sendMouseGesture` instead.
- The unused HTML link rewriting members `AddLinkAttribute` and `RewriteLinksToRelative` in
  `wh::filetypes/html.whlib` have been removed.
- The `whuser_appaccount` and `whuser_peerserver` types in user management schemas now link to `wrd_person` instead
  of `wrd_relation`. Existing schemas are migrated automatically.

## Deprecations
- Identifiers ending in `Url` now end in `URL`. The old names still work but are deprecated:
  - the `baseUrl` option of `rpc()`, `createClient()`, `getDirectOpenAPIFetch()` and `createUploadSession()` is now
    `baseURL`
  - `PSPRequest.returnUrl` and `pushUrl` in `@webhare/psp-base` are now `returnURL` and `pushURL`
  - `OpenIdAuthenticationParameters.finalUrl` in `@webhare/auth` is now `finalURL`
- `UploadInstructions.baseUrl` in `@webhare/upload` has been renamed to `baseURL` without an alias.
- `openType()` in `@webhare/whfs` is deprecated. Use `whfsType()`.
- HareScript `CreateQRCode` is deprecated. Use `GenerateQRCode` or `createQRCode` from `@webhare/graphics`.
- `JSRegEx` is deprecated, see the regular expressions section above.

## OAuth2 and dynamic client registration
WRD schemas can now act as a plain OAuth2 authorization server without being an OpenID Connect provider. This is
enough for dynamic client registration (RFC 7591) and for MCP clients.

- `/.well-known/oauth-authorization-server` (RFC 8414) is served for every identity provider site
- `/.well-known/openid-configuration` is only served if `loginSettings.openIdServer` is enabled. Otherwise it
  returns 404, and the `openid`, `profile` and `email` scopes and the userinfo endpoint are unavailable.

## New `wh wrd` commands
- `wh wrd edit-entity <id>` opens an entity's fields as YAML in your editor (`$VISUAL`, `$EDITOR` or `vi`), just like
  'Edit source' in the WRD browser, and updates the entity if you saved changes. To use Visual Studio Code:
  `EDITOR="code --wait" wh wrd edit-entity <id>`
- `wh wrd close-entity <id...>` closes one or more entities
- `wh wrd delete-entity <id...>` permanently deletes one or more entities
- `wh wrd update-entity` updates an entity, `wh wrd search` looks up entities by a field value, and
  `wh wrd get-setting` and `wh wrd update-setting` read and update schema settings

## Rotating cluster secrets
The cluster secrets (used for eg. cookies, image cache URLs, `wh-debug` signatures and encrypted data) can now be
rotated:
- `wh auth rotate-secrets [cache|cookie|debug|gcm|all...]` generates new secrets and keeps the old ones as retired
  secrets. Without arguments it rotates all of them. The cache secret signs image cache URLs in published pages, so
  republish your sites before disabling a retired cache secret. Add `--compromised` to stop accepting the old secrets
  immediately.
- `wh auth list-secrets` lists the current and retired secrets by fingerprint, and whether retired secrets are still
  being used according to the notice log.
- `wh auth disable-retired-secret`, `enable-retired-secret` and `delete-retired-secret` manage retired secrets.

Image cache (`/.uc/`) URLs signed with a retired cache secret keep working until that secret is disabled, so published
pages don't break before they're republished. Signatures (eg. `wh-debug`) are never accepted with a retired secret.
`decryptForThisServer` and HareScript `DecryptForThisServer` only accept data encrypted with a retired secret if you
pass the new `acceptRetired`/`acceptretired` option. Only use it for long-lived data that isn't security sensitive, eg.
form targets in published pages.

## Security
- All content under `/.uc/` is now served sandboxed, so eg. scripts in uploaded SVGs can't run.
- The captcha mock (`?wh-debug=nsc`) only works on development servers.
- Tollium icon names are validated before they are resolved to files.

## Other new `wh` commands
- `wh test create-user` creates a temporary test user and `wh test create-link` generates a login link for it. Test
  users always get the new `platform:debug` right, which gives access to the debugging options without being a sysop.
  Test users can't be created on production servers
- `wh whfs list-types [masks...]` lists the installed WHFS types (`--count` adds how often each type is used) and
  `wh whfs describe-type <type>` describes a type and its members
- `wh auth decode-jwt` decodes a JSON Web Token
- `wh devkit:edit <path>` opens a file (or a resource path) in the connected editor
- `wh devkit:container` builds and runs a WebHare source checkout (eg. a git worktree) in an isolated podman
  container. See `doc/devkit-containers.md`
- `wh event invalidate-file <path...>` reports changed files that the file watcher can't see, triggering the same
  recompiles as a change on disk

## WRD
- `close()` no longer moves the close date of entities that were already closed. Entities scheduled to close in the
  future are still closed now. If you relied on `close()` to bump the close date (eg. to restart a retention period),
  update `wrdClosed` explicitly instead.
- Queries on the `/wrd/` endpoints of the WebHare API accept a `historyMode` (`now`, `active`, `all` or
  `unfiltered`) and page through large types much faster.
- WRD history in TypeScript now supports rich text fields.
- `<values>` in a WRD schema definition can now set `DATE` (`YYYY-MM-DD`) and `DATETIME` (an ISO 8601 instant)
  attributes.
- `@webhare/wrd` exports `WRDInsertType` and `WRDUpdateType`, and the reusable `WRDEntityMatch` type. `update()` and
  `getFields()` accept a `WRDEntityMatch`.

## WHFS
- The `/whfs/` endpoints of the WebHare API return a 409 Conflict when creating an object that already exists, and
  errors include a `code` (eg. `object-exists` or `access-denied`). `@webhare/whfs` exports the underlying `WHFSError`
  class.

## Graphics
The new `@webhare/graphics` package offers `resizeImage` and `createQRCode`. HareScript code can use `ResizeImage` and
`GenerateQRCode` from `mod::platform/lib/graphics.whlib`, which are built on the same code and work on both the native
and the WASM engine.

## Backend services
Backend services hosted by the Node.js service manager are now restarted when their definition in
`moduledefinition.yml` changes. Set the new `revision` property of a service and change it with every update that
should restart the service (eg. when pushing a new version of the module). `wh service restart` now also works for
these services.

## Publisher and siteprofiles
- Siteprofile YAML components can use tids for their texts: a bare `tid` sets the component's `title`, and any
  `<x>Tid` property sets `<x>` (eg. `emptyTextTid` sets `emptyText`).
- The `webFeature` apply filter accepts masks and regular expressions, like the other filters, and matches
  case-insensitively.
- CSP site settings accept a `comment`, which isn't shown to unprivileged users.
- `allowmaxsignups="false"` on `<formintegration>` (`allowMaxSignups: false` in YAML siteprofiles) hides the "maximum
  number of signups" option in the form editor and ignores any configured maximum.
- Form conditions only offer the submit types that are relevant to the component, page or handler. Form handlers can
  adjust this through a new entry point in `FormHandlerBase`.
- When you clear the name of an existing file or folder, it's saved and published under the name suggested from its
  title, as shown in the placeholder.
- The Consilio tab of the Inspect dialog has an 'Index now' button that indexes the object and shows any errors.

## Other API additions
- The new Tollium `<svg>` component shows SVG images, which can be styled with CSS variables. SVGs from a module's
  `public/` folder are loaded by URL, so the browser can cache them.
- `createEphemeralEndpoint()` in `@webhare/router` sets up a temporary URL that routes requests to your callback,
  wherever it's running
- `createRedirectResponse()` accepts `URL` objects
- `getExcerpt()` on `RichTextDocument` returns a plain text version of the document, optionally limited in length
- `litty` templates accept `bigint`, `boolean`, `Date`, `URL`, `Money` and Temporal values. `null` and `undefined`
  print nothing
- `PageMetadata.consilioFields` in `@webhare/router` accepts nested records
- `createTrustedPortDispatcher()` in `@webhare/test-backend` sends `fetch()` requests through the local trusted port,
  like a trusted proxy would, so tests can simulate a client's IP address (`sourceIP`)
- `hasTid()` in `@webhare/gettid` tests whether a tid exists without logging a warning
- `createConcurrencyLimiter(jobs)` in `@webhare/std` limits how many callbacks run at the same time
- `isSafePropertyName()` and `isSafeObjectEntry()` in `@webhare/std` help protect against prototype pollution
- `FormBase.reset()` now sends `change` events to all controls, so components that track their own state (eg. custom
  select controls) can resync

## Tollium
- Sorting a list by clicking a column header keeps the selection. The keyboard cursor and shift-selection now follow
  the selected row when rows are reordered (by sorting, updates from the server or expanding/collapsing). A
  shift-selection replaces the existing selection, and if the only selected row disappears its closest remaining
  ancestor is selected.

## File permissions and temporary files in `@webhare/system-tools`
`storeDiskFile` accepts a `mode` option with the file permissions as an octal string, eg. `{ mode: "600" }`. The
permissions are applied before any data is written, so other users can't open the file while it's being written, and
aren't limited by the umask. Don't combine `mode` with `inPlace: true` for sensitive data: an existing file overwritten
in place may already be open by someone else.

The new `storeTempFile(name, data, options)` stores data in a new temporary file that is only readable by the current
user (unless you pass a different `mode`), in the system's temporary directory or the `dir` you pass. A random part is
inserted before the first dot of `name`, so `test.screens.yml` becomes eg. `test-<random>.screens.yml`. The returned
object has the file's `path` and an `unlink()` method, and removes the file when disposed:

```typescript
await using tempFile = await storeTempFile(`entity-${entityId}.yml`, yaml);
// use tempFile.path. The file is removed at the end of the block
```

Files that haven't been removed are also removed when the process exits or is terminated by SIGINT, SIGTERM or SIGHUP.
While temporary files exist, `storeTempFile` installs handlers for these signals. They only act if no other handler
exists for the signal, and then still let the signal terminate the process.

Use `moveTo(destination, { overwrite })` to move a temporary file to its final location once it's complete. It's then no
longer removed automatically.

## Validation
`wh validate` now also checks `.json` files (except `tsconfig.json`). Their JSON syntax is checked strictly (no
comments or trailing commas), and if their `$schema` property is a resource path (eg.
`mod::mymodule/data/settings.schema.json`) or a path relative to the file, they are validated against that schema.
YAML files without a module-specific validator are validated against their `$schema` in the same way.

`.schema.json`, `.schema.yml` and `.schema.yaml` files are compiled as a JSON Schema of the version in their `$schema`
property (draft-06, draft-07, 2019-09 or 2020-12, or 2020-12 if there's no `$schema`) in strict mode, so unknown
keywords are reported. Other `$schema` values, including draft-04, are reported as errors.

Files that passed validation before may now report errors. Exclude files that aren't meant to be valid JSON with an
`<exclude>` in your module's `<validation>` settings.

## Server roles
Servers can now have roles, so one module can run differently on different servers, eg. only send newsletters from
one server of a cluster.

Modules declare the roles they offer in `moduledefinition.yml`. The full name of a role is `<module>:<tag>`:

```yaml
serverRoles:
  mailer:
    title: Mail server   # or tid: module.serverroles.mailer
```

A server's roles are set on the Server tab of the global settings or with `wh config roles add` and
`wh config roles remove`, or by the host with the `WEBHARE_SERVERROLES` environment variable (full role names
separated by spaces or commas), which then overrides the configured roles. Changing the roles applies the full
configuration. `wh config roles list` lists all available roles and whether they're active, and the dashboard shows the
active roles below the server version.

WebHare also has built-in roles, which are always derived and can't be set: `platform:<dtapstage>` (eg.
`platform:production`), `platform:ci` if `WEBHARE_CI` is set and `platform:restored` in restore mode.

The configured roles are stored in the database, so a backup restored onto another server would bring them along. In
restore mode (`WEBHARE_ISRESTORED`) neither the configured roles nor `WEBHARE_SERVERROLES` are active. You can still
change the configured roles, eg. to set the restored server's own roles before it leaves restore mode.
`wh exit-restore-mode` refuses to continue while roles are configured, until you choose `--keep-serverroles` or
`--clear-serverroles`.

Restrict configuration to servers with a role:
- In `moduledefinition.yml`, `ifWebHare` accepts `serverRoles`, eg. `ifWebHare: { serverRoles: ["mymodule:mailer"] }`.
  Use `not` to exclude servers with a role.
- In XML, use `ifserverroles="mymodule:mailer"` or `unlessserverroles="mymodule:mailer"`.

A rule applies if the server has any of the listed roles. Role names must be exact, masks aren't supported.

To check roles in code, use `hasServerRole()` and `getServerRoles()` from `@webhare/services`, or `HasServerRole()` and
`GetServerRoles()` from `mod::system/lib/configure.whlib`.
