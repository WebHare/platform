# 6.1 - 15 October 2026

## Upgrade notes

- You MUST upgrade to WebHare 5.9.1 or higher and upgrade to Postgres 17 or higher before upgrading to WebHare 6.0 or 6.1.
  - But you should upgrade to at least WebHare 5.9.6 and deal with any reported deprecation warnings. Run `wh deprecationscan` manually for a direct report after updating (the built-in report in the dashboard is generated only once a week).
- WebHare 6.2 will remove support for DrawLib/wh::graphics bitmapped text-rendering APIs. We recommend using SVGs or Puppeteer's screenshot API for text image generation.
- We've moved to <https://github.com/WebHare/platform/> as our primary source code hosting location. Please submit new issues and pull requests there, or use <https://github.com/WebHare/platform/discussions> for community discussions, Q&A, etc.
- We've renamed the primary branch from 'master' to 'main'.

## Things that are nice to know

- Publisher
  - The version history dialog can query server-wide version history. Editors can inspect metadata and view earlier workflow versions.
  - Editor screens now include an Inspect Metadata action.
- Forms and Tollium
  - Frontend forms can update form variables and hidden fields dynamically; rich-value form components also support dynamic updates.
  - A form filter hook is available for custom spam filtering.
- Websites and webdesigns
  - `fsObjectPolicy` can suggest publication start and end dates and provide a live-preview placeholder for the Meta Title field.
  - TypeScript webdesign widgets can access the current web request and content instance, and append structured data to the page.
  - Content links are transparent to apply rules, which now use the final file type when determining applicable rules.
  - Mark whfsTypes whose properties can be set for content link files with `contentLink: true` in their siteprofile definition. `getInstanceData` on WebDesign/pageRequest objects will honor this flag.
  - Set `ogimageresource` or `pageMetaData.imageResource` to have WebHare determine the format, scaling, and absolute URLs for OpenGraph metadata.
- Authentication
  - OpenID Connect login supports PKCE, returns the user's email in userinfo, and avoids prompting for scopes already granted.
- WRD
  - The `delete()` API now limits deletion to entities of the type on which it was called, preventing accidental mixing of IDs.
  - The HareScript API now supports UUIDs in `Search`/`RunQuery` queries for `WRD_GUID` fields, eliminating the need to use `UUIdToWRDGuid`.
- Developer tooling
  - The WebHare language server now lets you follow resource paths in XML/YML files and jump to their definitions with F12 in VS Code.

## TypeScript/JavaScript highlights

- Generic
  - `createWebResponse` accepts `litty` template literals.
- Frontend
  - `waitForElement` accepts `Element` and SVG elements, and supports more selector types.
- Backend
  - The WHFS API adds `LookupURL` for resolving WHFS URLs.
  - `getInstanceSource` identifies the object ID to use when querying a filesystem type.
  - TypeScript webdesign routers can invoke HareScript routers and support dynamic page parameters and router subcalls.
  - Image-cache conversions now run in the JavaScript service, including AVIF conversion paths.
- Testing and debugging
  - `test.transitionsToTrue` checks whether a condition became true because of the action being tested, and `test.scopedPrefix` prefixes failure annotations.
  - `wh harescript-debug locks <pid>` lists locks held by a process.

## Incompatibilities and deprecations

- Image resize methods `stretch`, `stretch-x`, `stretch-y`, `crop` and `cropcanvas` are no longer supported.
- Configurable output extensions are no longer supported.
- The `wh ssl` command is now `wh crypto`. Subcommands are hyphenated; use the global `--json` option instead of `--format json`.
- The deprecated `CreateImageEditDialog` and `TolliumImageEdit` components have been removed.
- Deprecated authentication exports have been removed from their former package; use `@webhare/auth`.
- WebHare 6.1 ignores `towl` `<notification>` elements in `moduledefinition.xml` files; use `moduledefinition.yml` instead.
- `onsetenabled` in richdocument has been removed. Use `editdocumentapi->AddEventListener("readonly", ...)` instead. Consider `GetWebhareVersionNumber()` if you need to support both 6.1 and earlier versions.
